1. API
    1-1. 다른 프로그램의 기능을 사용할 수 있도록 제공하는 인터페이스입니다.
    1-2. 인터넷을 통해 외부 서버의 기능을 사용할 수 있고 이를 웹 API라고 합니다.


2. RestAPI
    2-1. 네트워크를 통해 시스템 간에 데이터를 주고받는 데 사용하는 아키텍처 스타일입니다.
    2-2. RestAPI는 아래의 설계 원칙을 따릅니다.
        => URL을 이용하여 어떤 리소스에 접근할 것인지 지정한다.
        => HTTP 메서드를 이용하여 어떤 작업을 수행할 것인지 지정한다.
        => JSON 등의 형식으로 데이터를 주고받는다.
        => HTTP 상태 코드를 이용하여 요청 처리 결과를 표현한다.
        => 각 요청은 서버가 처리하는 데 필요한 정보를 포함한다(무상태성).
    

3. HTTP 요청 구조
    3-1. 클라이언트가 서버의 기능을 사용하기 위해 보내는 메시지를 HTTP 요청이라고 합니다.
    3-2. 예시
        => 새로운 학생을 생성하기 위한 HTTP/1.1 요청
        POST /students HTTP/1.1
        Host: example.com
        Content-Type: application/json
        Content-Length: 26

        {"name":"hong","age":20}
    
    3-3. HTTP 요청 분석
        => Request Line, Headers, Body 세 부분으로 나뉩니다.

        1. Request Line은 POST /students HTTP/1.1
            구성 요소       의미
            POST	      HTTP 메서드 (서버에 어떤 종류의 작업을 요청하는지 나타냅니다.)
            /students	  요청 대상 경로
            HTTP/1.1	  HTTP 프로토콜 버전
        
        2. Headers
            Host: example.com
            Content-Type: application/json
            Authorization: Bearer example-key

            헤더	             역할
            Host	            요청 대상 호스트
            Content-Type	    본문 데이터의 형식
            Content-Length	    본문 데이터의 바이트 길이
            Authorization	    인증 정보
            Accept	            클라이언트가 받고 싶은 응답 형식
        
        3. Body -> {"name": "hong","age": 20}
            => 서버에 전달할 실제 데이터입니다.


4. URL 구조
    4-1. https://api.example.com:443/students?age=20
    4-2. https -> 프로토콜
    4-3. api.example.com -> 호스트-접근할 서버의 도메인 이름
    4-4. 443 -> 포트
    4-5. /students -> 경로, 요청할 리소스의 경로
    4-6. ?age=20 -> 쿼리 문자열, 추가적인 요청 조건


5. HTTP 응답 구조
    5-1. 예시
    => 학생 생성 성공 시 보내는 HTTP 응답
    HTTP/1.1 201 Created
    Content-Type: application/json

    {
        "id": 1,
        "name": "hong",
        "age": 20
    }

    5-2. HTTP 응답
        => Status Line, Headers, Body 세 부분으로 나뉩니다.


6. HTTP 상태 코드(Status Code)
    6-1. 범의
        범위	 의미
        1xx	    정보 전달
        2xx	    요청 처리 성공
        3xx	    리다이렉션
        4xx	    클라이언트 측 요청 문제
        5xx	    서버 측 문제
    
    6-2. 주요 상태 코드
        상태 코드	                  의미	              발생 상황
        200 OK	                    성공	           AI 생성 결과 반환
        201 Created	                생성 성공	        리소스 생성
        400 Bad Request	            잘못된 요청	         요청 데이터 오류
        401 Unauthorized	        인증 실패	        API Key 누락 또는 잘못된 키
        403 Forbidden	            접근 거부	        사용 권한 부족
        404 Not Found	            대상 없음	        잘못된 엔드포인트
        429 Too Many Requests	    요청 제한	        호출 한도 초과 등
        500 Internal Server Error	서버 내부 오류	     서버 처리 실패
        503 Service Unavailable	    서비스 이용 불가	  서버 과부하 등


7. python에서 HTTP 요청 보내기
    7-1. Python에서 requests라는 외부 라이브러리를 사용하면 HTTP 요청을 편리하게 보낼 수 있습니다.
    7-2. 표준 라이브러리가 아니므로 별도로 설치해야 합니다. (python -m pip install requests)
    
    7-3. Get 요청
        import requests

        response = requests.get(
            "https://example.com"
        )

        print(response.status_code)
        print(response.text)
        => response는 requests 라이브러리가 제공하는 Response 클래스의 객체입니다.
    
    7-4. Post 요청
        import requests

        url = "https://api.example.com/students"

        headers = {
            "Content-Type": "application/json"
        }

        data = {
            "name": "hong",
            "age": 20
        }

        response = requests.post(
            url,
            headers=headers,
            json=data,
            timeout=30
        )

        인수	             의미
        url	                요청을 보낼 대상
        headers=headers	    HTTP 요청 헤더
        json=data	        JSON으로 변환하여 전달할 본문
        timeout=30	        네트워크 연결 및 응답 대기 타임아웃 설정(초)


8. HTTP 응답 처리
    8-1. python이 http 응답을 받고 Response 클래스의 객체로 구성하고 반환합니다.
        => response가 http 응답에 관한 정보를 가지고 있는 객체입니다.
        => response.status_code = 200;
        => response.headers = 문자열
        => text = body_문자열
    8-2. response.json()
        => text가 객체 모양을 갖춘 문자열, json() 호출 -> dict 형태로 반환합니다.


9. HTTP 예외 처리
    9-1. 서버가 401을 반환하더라도 requests는 기본적으로 HTTPError 예외를 발생시키 않습니다.
        => 서버가 요청을 거부하기는 했지만, HTTP 요청을 보내고 응답을 받아오는 통신 자체는 성공했기 때문입니다.

    9-2. response.raise_for_status()
        => HTTP 상태 코드를 검사하여 4xx 또는 5xx이면 HTTPError 예외를 발생시킵니다.
            상태 코드	 raise_for_status() 동작
            200	        정상 통과
            201	        정상 통과
            400	        HTTPError 발생
            401	        HTTPError 발생
            404	        HTTPError 발생
            429	        HTTPError 발생
            500	        HTTPError 발생
    
    9-3. 인터넷 연결이 끊기거나, 응답 대기 시간이 초과하면 raise_for_status()에 도달못하고 
            request.gets() 자체에서 예외가 발생할 수 있습니다.
        => RequestException를 이용해서 한꺼번에 처리할 수 있습니다.
        => HTTPError, ConnectionError, Timeout 등은 RequestException을 상속받는 예외 클래스입니다.
