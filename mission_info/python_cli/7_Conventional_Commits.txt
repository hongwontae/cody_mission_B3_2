1. Conventional Commits
    1-1. Git 커밋 메시지를 일정한 형식에 맞춰 작성하기 위한 규약입니다.
    1-2. 일반적으로 Git에서는 커밋 메시지를 자유롭게 작성할 수 있습니다.
        => 이렇게 작성하면 나중에 어떤 목적으로 코드를 변경했는지 파악하기 어렵습니다.
    1-3. Conventional Commits에서는 다음과 같은 형식을 사용합니다.
        => git commit -m "feat: 로그인 기능 추가"
        => git commit -m "fix: 로그인 오류 수정"
        => git commit -m "docs: README 수정"


2. Conventional Commits의 기본 구조
    2-1. type scope : description
    2-2. Type — 변경 유형
        => 어떤 종류의 변경이 발생했는지를 나타냅니다.
        =>  Type	    의미
            feat	    새로운 기능 추가
            fix	        버그 수정
            docs	    문서 변경
            style	    코드 공백, 들여쓰기 등 동작에 영향이 없는 변경
            refactor	기존 동작을 유지하면서 코드 구조 개선
            perf	    성능 개선
            test	    테스트 코드 추가 및 수정
            chore	    기타 프로젝트 유지보수
            build	    빌드 시스템 및 의존성 변경
            ci	CI/CD   설정 변경
    
    2-3. Scope — 변경 범위
        => 프로젝트의 어느 부분을 변경했는지 나타냅니다.
    
    2-4. Description — 변경 내용
        => 실제로 무엇을 변경했는지 간결하게 설명하는 부분입니다.
