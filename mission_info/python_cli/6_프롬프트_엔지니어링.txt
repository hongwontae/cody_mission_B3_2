1. 프롬프트
    1-1. AI 모델에 원하는 작업을 수행하도록 전달하는 입력입니다.
    1-2. 단순한 질문뿐만 아니라 명령, 역할, 참고 데이터, 출력 형식, 제약 조건 등도 포함할 수 있습니다.


2. 프롬프트 설계가 중요한 이유
    2-1. 같은 AI 모델에 동일한 Git diff를 제공하더라도 어떤 지시를 내리느냐에 따라 결과가 달라질 수 있습니다.
    2-2. 예시
        void Student::setAge(int value) {
        +   if (value < 0) {
        +       return;
        +   }
            age = value;
        }

        => 프롬프트 A : 이 코드를 설명해 줘.
        => 이 코드는 나이가 음수인 경우 함수의 실행을 종료하도록 수정되었습니다.

        => 프롬프트 B : 다음 Git diff를 분석하여 Conventional Commits 형식으로 한국어 커밋 메시지를 작성해 줘.
             메시지는 한 줄로 작성하고 부가 설명은 생략해.
        => fix: 음수 나이 입력 방지


3. 프롬프트 구성 요소
    구성 요소	      의미
    Role	        AI가 어떤 역할을 수행하는가
    Instruction	    어떤 작업을 수행해야 하는가
    Context	        작업에 필요한 배경 정보는 무엇인가
    Constraint	    어떤 규칙과 제한을 지켜야 하는가
    Output Format	어떤 형태로 결과를 반환해야 하는가


4. System Prompt와 User Prompt
    4-1. System Prompt
        => AI가 어떤 역할을 수행하고 어떤 규칙을 지켜야 하는지 설정하는 메시지입니다.
        => {
            "role": "system",
            "content": """
                    당신은 Git 커밋 메시지 생성 도우미입니다.
                    한국어로 작성하세요.
                    한 줄로만 작성하세요.
                """
            }
        => AI에게 업무 지침서를 전달하는 것과 비슷합니다.
    
    4-2. User Prompt
        => AI에게 실제로 수행할 작업이나 분석할 데이터를 전달하는 메시지입니다.
        => {
            "role": "user",
            "content": """
                다음 Git diff를 분석하세요.

                - int age = 10;
                + int age = 20;
            """
            }
        => 실제 업무를 전달하는 것과 비슷합니다.


5. Zero-shot Prompting
    => 별도의 예시 없이 작업을 지시하는 방식입니다.
    => AI가 기존에 학습한 지식을 바탕으로 결과를 생성합니다.

6. One-shot Prompting
    => 하나의 예시를 제공하는 방식입니다.

7. Few-shot Prompting
    => 여러 개의 예시를 제공하는 방식입니다.


8. 프롬프트 인젝션(Prompt Injection)
    => Git diff에는 소스 코드뿐만 아니라 주석이나 일반 텍스트도 포함될 수 있습니다.
    => AI가 이러한 내용을 분석 대상 데이터가 아닌 새로운 명령으로 해석할 가능성이 있습니다.
    => 이러한 공격 기법을 프롬프트 인젝션이라고 합니다.
    => 이를 줄이기 위해 System Prompt에서 제한을 걸 수 있습니다.
