1. Git Pull Request
    => PR은 내가 작업한 브랜치의 변경 내용을 다른 브랜치에 합쳐 달라고 요청하는 것입니다.
    => PR을 만들면 GitHub에서 다른 개발자에게 변경 내용을 검토받을 수 있습니다.
    => 검토 후 문제가 없다면 PR을 병합(Merge)해서 main에 변경 사항을 반영할 수 있습니다.


2. git status
    2-1. 현재 파일들이 어떤 상태인지 알려줍니다.


3. git diff
    3-1. Working Directory와 Staging Area의 차이를 비교합니다.
    3-2. 실제로 어떤 코드가 변경되었는지 보여줍니다.
    3-3. +가 붙은 줄은 추가된 코드이고 -가 붙은 줄은 삭제된 코드입니다.
    3-4. git add .를 하면 아무것도 보이지 않습니다.
        => add .를 하면 변경 사항이 staging area로 가기 때문입니다.
    3-5. git diff --cached
        => 마지막 커밋(HEAD) ↔ Staging Area를 비교합니다.
    3-6. git diff HEAD
        => 마지막 커밋(HEAD) ↔ Working Directory를 비교합니다.
